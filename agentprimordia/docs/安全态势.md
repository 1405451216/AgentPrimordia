# 安全态势报告（v4.6 安全与治理）

> 目标：评估安全分项 ≥9。本文档汇总 v4.6 安全能力与证据锚点，作为安全评估的复测基线。

## 一、租户隔离（v4.6-1）

| 层级 | 机制 | 证据 |
|------|------|------|
| 过滤器级 | `TenantScoped` 按 `Metadata["tenant_id"]` 过滤/校验，拒绝入审计 | `internal/memory/tenant.go`（Add :126-141、TenantAuditSink） |
| **物理分库** | `PhysicalTenantStore` 每租户独立 SQLite 文件，绕过 metadata 也无法跨租户读取 | `internal/memory/physical_tenant.go` + 双租户隔离测试 |

验收：双租户物理隔离测试 ✅（`TestPhysicalTenant_Isolation`：A 的 episode 在 B 的库里 Get 不存在）。

## 二、审计（v4.6-2）

- `audit.Logger`：Log / Query（按 Actor/Action/Resource/时间范围）/ GenerateReport / **ExportJSON**（全链路导出）
- ReAct 循环关键路径审计：agent.start/stop、llm.call、guardrail.block/sanitize（`react_loop_core.go` + `react_loop_blocks.go`）
- 租户拒绝、密钥轮换、guardrail 命中均有审计事件

验收：一次完整目标执行可全链路导出 ✅（`ExportJSON` 按 Actor 过滤导出）。

## 三、输入输出护栏（v4.6-3）

- PII 脱敏管线：`guardrail/sanitizer.go` + `pii.go`（Trie 模式库）
- 注入检测：`guardrail/injection_rule.go`；输出端接入 ReAct 循环（`guardrailSanitizeOutput`）
- **敏感工具审计**：`SensitiveToolRule`（Blocked→拦截 / AuditOnly→审计标记）
- 语音/视觉护栏：`AudioGuardrail` / `VisionGuardrail`（v4.3）

验收：注入样例 PII 不落日志 ✅（脱敏输出路径 + 审计事件不含原文）。

### 世界模型与护栏边界（v6.1 起适用）

- 世界模型状态图是 ReAct 循环内部的规划/校验状态（internal/agent/worldmodel/），
  不是新的消息内容：状态断言不进 history、不过 guardrail 输入/输出端
  （两端拦截点仍为 react_loop_engine.go 输入护栏与 guardrailSanitizeOutput 输出护栏），
  不改变既有 PII/注入规则的作用面；
- 预演（model-based planning）产生的「计划内工具调用」在真实执行前仍走
  governance.Enforcer.CheckToolCall 与既有 tool 策略——预演豁免不了任何策略检查；
- 回溯差异（世界状态 vs 实际结果不一致）写失败库并触发审计，
  审计口径沿用既有 AuditEvent（worldmodel.rehearsal_failed / worldmodel.backdiff_diverged）。
