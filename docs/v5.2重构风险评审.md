## 一、策略接口冻结点清单

| 冻结点 | 位置 | 说明 |
|--------|------|------|
| Strategy 接口 | `internal/agent/strategy/strategy.go` | `Name() / Run(ctx, Task)` 两方法；v5.x 内不再变更签名 |
| Engine 原语接口 | 同上 | Complete / ExecuteTool 最小依赖面；策略不直接依赖 react_loop 内部 |
| Verifier 接口 | `internal/agent/strategy/verifier.go` | `Verify(ctx, task, output)`；新增校验器只做加法 |
| PlanCheckpoint schema | `internal/agent/strategy/plan_checkpoint.go` | JSON 字段只增不改；SubTask 复用 planning 包既有序列化 |

## 二、Feature-flag 回滚开关方案

1. **新增式隔离**：全部新代码位于 `internal/agent/strategy/` 新子包，零改动 react_loop 热路径——回滚 = 删除包引用，主路径不受影响。
2. **显式注册制**：策略经 `strategy.Register()` 注册、`registry.Get(name)` 取用；默认策略未设置时返回错误而非静默回退，杜绝隐式切换。
3. **热切换并发安全**：Registry 用 RWMutex 保护 SetDefault；切换仅影响后续 Run，进行中的 Run 不受影响。
