# v2.0.0 实施计划 — 移除 ReActConfig Deprecated 字段

> **日期**: 2026-06-17
> **状态**: Approved
> **版本**: v2.0.0
> **前置**: v1.0.0 panic on invoke（已完成）
> **破坏性变更**: 是 — 编译期失败（必须改代码）

## 1. 背景与动机

v1.0.0 已经让设置 Deprecated 字段在运行时 panic，但字段本身仍在 `ReActConfig` struct 中。这导致：
- 编译期仍可见，IDE 自动补全仍列出 14 个废弃字段
- 代码体积大（23 个字段，14 个已废弃）
- 维护负担（NewReActAgent 内部仍需处理兼容逻辑）

v2.0.0 彻底移除这些字段，让编译期就能阻止误用。

## 2. 影响范围

### 2.1 需要删除的 14 个字段

从 `ReActConfig` struct 中移除：
- Toolkit *tools.Registry
- Memory MemoryStore
- EventPublisher EventPublisher
- Metrics MetricsRecorder
- ContextWindow ContextWindowStrategy
- CheckpointStore persist.CheckpointStore
- RAG *RAGConfig
- Hooks Hooks
- Summarizer memory.SummaryExtractor
- FileScope []string
- HITL *HITLConfig
- CostTracker *CostTracker
- Tracer Tracer
- Cache llm.LLMCache

### 2.2 需要删除的文件

- `internal/agent/deprecated_check.go` — 不再需要 panic 检查

### 2.3 需要更新的代码

- `internal/agent/react_loop.go` — `NewReActAgent` 函数移除对这些字段的处理
- `internal/agent/capability_agent.go` — 链式 API 保留（这是新的注入方式）
- 所有测试文件（如果还有引用）
- 所有文档

### 2.4 保留的内容

- `NewReActAgent` 函数本身保留（只接受标量配置）
- 链式 API（WithToolkit/WithMemory 等）保留
- `NewAgent` + Functional Options 保留
