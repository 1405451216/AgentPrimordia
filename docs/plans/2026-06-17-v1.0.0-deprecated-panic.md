# v1.0.0 实施计划 — ReActConfig Deprecated 字段 panic on invoke

> **日期**: 2026-06-17
> **状态**: Approved
> **版本**: v1.0.0
> **前置**: v0.7.0 API 稳定化 + Deprecated 标记（已完成）
> **后续阻塞**: v2.0.0（移除 ReActConfig 字段）
> **破坏性变更**: 是 — 设置 Deprecated 字段将 panic

## 1. 背景与动机

按照废弃时间表（semver-policy.md §4.2）：
- v0.7.0: 替代 API 升级为 Stable; 旧 API 加 Deprecated 标注 ✅
- v0.8.0: 旧 API 编译期 warning ✅
- v0.9.0: panic if invoked in strict mode ⏭️ 跳过
- **v1.0.0: 旧 API panic on invoke (强制迁移)** ← 当前
- v2.0.0: 旧 API 移除

用户决定跳过 v0.9.0（strict mode），直接做 v1.0.0（强制 panic）。

## 2. 设计决策

### 2.1 panic 触发条件

**NewReActAgent 函数本身不 panic**（否则 buildAgent 会崩溃）。
**当 cfg 的 14 个 Deprecated 字段任一非 nil/非零时 panic**。

这样：
- `buildAgent` 只传标量字段 → 不 panic ✅
- 纯标量配置的 `NewReActAgent(ReActConfig{Name:..., Model:...})` → 不 panic ✅
- 设置了 Deprecated 字段的 `NewReActAgent(ReActConfig{Toolkit: reg, ...})` → panic ❌

### 2.2 panic 消息

```
panic: ReActConfig.Toolkit is deprecated and no longer accepted in v1.0.0;
use NewAgent(name, prompt, model, WithToolkit(registry)) instead.
See: ecosystem/docs/migration/v0-deprecations.md
```

### 2.3 受影响的 14 个字段

Toolkit, Memory, EventPublisher, Metrics, ContextWindow, CheckpointStore,
RAG, Hooks, Summarizer, FileScope, HITL, CostTracker, Tracer, Cache
