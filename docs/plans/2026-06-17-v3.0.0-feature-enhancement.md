## 3. 新增功能详细设计

### 3.1 PlanningCapable — 任务分解和计划生成

**接口定义**：
```go
type PlanningCapable interface {
    GetPlanner() Planner
}

type Planner interface {
    // Decompose 将复杂任务分解为子任务列表
    Decompose(ctx context.Context, task string) ([]SubTask, error)
    // GeneratePlan 生成执行计划（包含依赖关系）
    GeneratePlan(ctx context.Context, task string) (*Plan, error)
}

type SubTask struct {
    ID          string
    Description string
    DependsOn   []string  // 依赖的子任务 ID
    Status      TaskStatus
    Result      string
}

type Plan struct {
    Goal      string
    SubTasks  []SubTask
    CreatedAt time.Time
}

type TaskStatus string
const (
    TaskPending   TaskStatus = "pending"
    TaskRunning   TaskStatus = "running"
    TaskCompleted TaskStatus = "completed"
    TaskFailed    TaskStatus = "failed"
)
```

**实现要点**：
- `Planner` 使用 LLM 进行任务分解
- 支持 DAG（有向无环图）表示任务依赖
- 提供默认实现 `LLMPlanner`

**文件结构**：
```

├── llm_planner.go      # LLM 实现
```


### 3.2 ReflectionCapable — 自我反思和纠错

**接口定义**：
```go
type ReflectionCapable interface {
    GetReflector() Reflector
}

type Reflector interface {
    // Reflect 对执行结果进行反思
    Reflect(ctx context.Context, input, output string) (*Reflection, error)
    // Critique 对输出进行批评和纠错
    Critique(ctx context.Context, output string) (*Critique, error)
    // Improve 基于反思结果改进输出
    Improve(ctx context.Context, output string, feedback *Critique) (string, error)
}

type Reflection struct {
    Strengths    []string
    Weaknesses   []string
    Suggestions  []string
    Confidence   float64
}

type Critique struct {
    Issues       []Issue
    Severity     Severity
    Corrections  []Correction
}

type Issue struct {
    Description string
    Location    string
    Severity    Severity
}

type Severity string
const (
    SeverityLow      Severity = "low"
    SeverityMedium   Severity = "medium"
    SeverityHigh     Severity = "high"
    SeverityCritical Severity = "critical"
)

type Correction struct {
    Original  string
    Corrected string
    Reason    string
}
```

**实现要点**：
- `Reflector` 使用 LLM 进行自我反思
- 支持多维度评估（准确性、完整性、一致性等）
- 提供默认实现 `LLMReflector`

**文件结构**：

### 3.7 supervisor 协作模式 — 主从式任务分配

```go
type Supervisor struct {
    name      string
    workers   []Agent
    strategy  AssignmentStrategy
}

type AssignmentStrategy interface {
    // Assign 将任务分配给最合适的 worker
    Assign(ctx context.Context, task string, workers []Agent) (Agent, error)
}

// 内置策略
type RoundRobinStrategy struct{}      // 轮询
type LoadBalancedStrategy struct{}    // 负载均衡
```

**工作流程**：
1. Supervisor 接收任务
2. 根据策略选择最合适的 worker
3. 将任务分配给 worker 执行
4. 收集结果并返回

### 3.9 pipeline 协作模式 — 流水线式任务处理

**接口定义**：
```go
type Pipeline struct {
    name  string
    stages []Stage
}

type Stage struct {
    Name    string
    Agent   Agent
    Timeout time.Duration
    OnError ErrorStrategy
}

type ErrorStrategy string
const (
    ErrorAbort   ErrorStrategy = "abort"    // 中止整个流水线
    ErrorSkip    ErrorStrategy = "skip"     // 跳过当前阶段
    ErrorRetry   ErrorStrategy = "retry"    // 重试
    ErrorFallback ErrorStrategy = "fallback" // 使用备用方案
)

type PipelineResult struct {
    StageResults []StageResult
    Duration     time.Duration
    Status       PipelineStatus
}

type StageResult struct {
    StageName string
    Output    string
    Error     error
    Duration  time.Duration
}

type PipelineStatus string
const (
    PipelineSuccess PipelineStatus = "success"
    PipelinePartial PipelineStatus = "partial"
    PipelineFailed  PipelineStatus = "failed"
)

func NewPipeline(name string, stages []Stage) *Pipeline
func (p *Pipeline) Execute(ctx context.Context, input string) (*PipelineResult, error)
```

**工作流程**：
1. 输入传递给第一个 Stage
2. 每个 Stage 的 Agent 处理输入并产生输出
3. 输出作为下一个 Stage 的输入
4. 收集所有 Stage 的结果

**文件结构**：
```
internal/orchestration/pipeline/
├── pipeline.go         # Pipeline 实现
├── stage.go            # Stage 定义
├── pipeline_test.go    # 单元测试
└── README.md           # 使用文档
```

## 5. 每个 Task 的实施流程

每个 Task 遵循 TDD 流程：

1. **Red**: 编写失败的测试
2. **Green**: 实现最小代码使测试通过
3. **Refactor**: 重构代码，保持测试通过

每个 Task 完成后：
- 运行 `go test ./...` 确保所有测试通过
- 运行 `go vet ./...` 确保无警告
- 运行 `gofmt -l` 确保代码格式正确
- 提交代码（commit message: `feat: add XxxCapable` 或 `feat: add xxx tool`）

## 7. 风险和缓解

### 7.1 技术风险
- **风险**: code_execution 工具的安全漏洞
  - **缓解**: 使用进程隔离、资源限制、网络隔离
- **风险**: database 工具的 SQL 注入

- **风险**: api 工具的认证信息泄露
  - **缓解**: 使用环境变量、加密存储

- **风险**: 9 个功能模块工作量大
