# AgentPrimordia v6.0 路线图实施计划（v5.1 – v6.0）

> **文档定位**：v5.0 平台里程碑收官（加权复测 ≈8.8/10）后，v5.1–v6.0 的均衡混排弧线——奇数版本能力深化、偶数版本工程稳定，逐版本推进到 v6.0 生态跃迁主版本。
>
> **创建日期**：2026 年 8 月 19 日　**版本基线**：Go SDK v5.0.0 / TypeScript SDK v5.0.0
>
> **弧线主题**：深耕与飞轮（Deep Cultivation & Flywheel）——前半弧（v5.1–v5.5）把已接线的能力**深耕到质量可量化、体验可感知**；后半弧（v5.6–v6.0）把质量**认证化**、把运营**规模化**，以 v6.0 主版本完成「平台 → 生态飞轮」跃迁。
>
> **粒度约定**：v5.1 为首个可实施版本（全量任务表，临近开工时细化到文件级）；v5.2–v6.0 为里程碑粒度，临近时按 V5-ROADMAP 四层结构（核心实现/跨组件集成/开发者体验/测试与性能验证）深化。

---

## 一、弧线总原则（延续 v4.1–v5.0 并加强）

| # | 原则 | 说明 |
|---|------|------|
| 1 | 均衡混排 | 奇数版本=能力深化（记忆/多模态/体验/性能/智能），偶数版本=工程稳定（评估/运维/安全/生态/收官）；弧线整体不偏科 |
| 2 | 端到端验收 | 每版本一个可运行、可复现的验收场景（见进度跟踪表） |
| 3 | 双语言同步 | 新增 Go 能力在 TS SDK 对等实现并纳入 cross-language-spec 套件（当前 57 用例基线） |
| 4 | TDD 强制 | 每任务先写测试，验证门 `make test-short` 或变更包测试，失败即停（AGENTS.md §6.1） |
| 5 | 向后兼容 | 全部新增式演进；冲突路径标 `Deprecated:` + `Removed in vX.Y` 引导迁移，仅 v6.0 主版本按 VERSIONING 执行移除 |
| 6 | 实证记录 | 每版本完成更新 ROADMAP.md 状态并附代码证据（文件:行号）与量化数据，复测深度评估分项 |
| 7 | 依赖白名单 | 仅标准库 + 白名单依赖（AGENTS.md §2.1）；真实服务一律「接口 + 可插拔适配器」 |
| 8 | 质量先于数量（本弧线新增） | 每版本至少 1 个**量化质量指标**进入回归门（召回率/成功率/P95/命中率），杜绝"功能存在但质量不可知" |

## 三、v5.1 记忆与检索质量（Memory & Retrieval Intelligence）

> **性质**：能力深化
> **本质跃迁**：从「记忆能存能搜」到「检索质量可量化、可回归、可信任」。
> **立项证据**：TS HNSW `search()` 召回率实测 ≈0.7（瓶颈为 level-0 BFS 候选上限，`sdk/typescript/src/memory/vector-extended.ts` search() 中 `candidates.length < ef` 截断）；Go/TS 均无召回率基准套件；三层记忆是框架核心卖点但质量不可知。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | TS HNSW `search()` 真实 ef-search | level-0 改为与 Go 对齐的 beam search（保留 visited/提前退出语义），替换 BFS 截断遍历；300/1000/3000 向量三档、固定种子数据集，recall@10 ≥ 0.95（暴力 kNN 基准） |
| 2 | 双线召回基准套件 | cross-language-spec 新增 `vector_search_quality` 套件（固定种子向量集 + 查询集 + 期望召回下界），Go/TS 双侧实现并通过 |
| 3 | RAG 检索质量量化 | rag-pipeline 建立带 ground-truth 文档集的检索精度测量（Hit@k / MRR），纳入回归门并产出基线数值 |
| 4 | 记忆回读效果度量 | v3.4 已接线的 MemoryStore.Search 回读注入，建立「相似任务成功率/推理轮数」对照度量，量化回读收益 |
| 5 | Go 侧对齐核查 | Go `InMemoryStore`/HNSW 路径与 TS 新实现对齐核查，行为差异入 cross-language-spec |

**验收场景**：同一固定数据集上，Go/TS 双线 recall@10 ≥ 0.95 且差值 ≤ 0.02；RAG Hit@k 基线报告入库 `bench/results/`。

**外部依赖**：无（纯代码可闭环）。

## 四、v5.2 评估体系常态化（Eval Operations）

> **性质**：工程稳定
> **本质跃迁**：从「评估能跑」到「评估按夜运转、数字可信、漂移有警报」——关闭 v5.0 复测残余风险 #1。
> **立项证据**：v5.0 复测残余风险「真实 LLM 跑分数值与 24h Soak 正式报告依赖 API Key/长时环境（nightly CI 执行）」；llm_bench 四类跑分（编码/autonomy/skills/双线对照）与 2026-Q4 基线已具备。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | nightly 真实 LLM 跑分常态化 | CI secrets 注入 + nightly 双线跑分真实执行；分数漂移超阈值（如 ±10%）自动告警；连续 7 天有产出 |
| 2 | 24h Soak 正式报告 | 基于 v4.2 soak harness（恢复率 1.0 基线）产出正式 24h 报告：恢复率/退化/P95 全量数据入库 |
| 3 | 排行榜发布自动化 | 每次发布自动更新 `bench/results/` 排行榜（成功率/成本/延迟三列），随 tag 触发 |
| 4 | 评估数据集扩容 | 60 条编码基准 → 覆盖 autonomy/skills/multi-agent 领域，总量 ≥150 条，双线共用 |
| 5 | 评估分项复测 | 「评估体系」分项目标 ≥9.0（v5.0 基线 8.5） |

**验收场景**：任意一周可查看 nightly 真实跑分曲线 + 24h Soak 正式报告 + 自动更新的榜单页。

**外部依赖**：⚠️ 需要仓库 secrets 配置 LLM API Key（维护者操作）。

## 五、v5.3 多模态产品化（Multimodal Production）

> **性质**：能力深化
> **本质跃迁**：从「语音/视觉链路已接通」（v4.1/v4.3）到「体验与产品相当」。
> **立项证据**：v4.3 流式语音链路 + 视觉护栏/帧分析已真实接线，但交互完整度（打断/端点检测）与浏览器端推理未产品化；残余风险 #2（WebGPU 浏览器端到端需 GPU 环境）。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | 全双工语音交互 | 打断处理 + 端点检测 + 轮次衔接延迟测量：端到端响应延迟 P95 基线入库并达目标值 |
| 2 | WebGPU 浏览器 E2E | GPU 环境下真实浏览器端到端推理 demo（关闭残余风险 #2）；CI 以 manual label 门控 |
| 3 | 视觉入 loop | 帧分析结果作为 ReAct 工具输入，视觉 QA 验收场景通过（看图回答 + 护栏联动） |
| 4 | 边缘推理落地 | edge-inference-profile 从文档到实现：WebGPU/本地量化模型延迟与内存实测基线 |

**验收场景**：一次可打断的多轮真实语音对话 + 一次浏览器内 WebGPU 推理 + 一次视觉问答，三者均有录屏/日志证据。

**外部依赖**：⚠️ WebGPU 需 GPU 浏览器环境（可用 CI self-hosted runner 或本地验收）。

## 九、v5.7 性能与成本第二轮（Perf & Cost II）

> **性质**：能力深化
> **本质跃迁**：从「单点优化」（v4.9：WAL 写 P95 -98% 等）到「端到端体验与成本基线」。
> **立项证据**：v4.9 第一轮已完成单点优化并刷新 2026-Q4 基线；TS 上下文压缩（KeepLastN/TokenBudget）比 Go 先进（CAPABILITY-INVENTORY 记录），双线未对齐。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | 关键路径延迟第二轮 | 首 token / 流式 / 工具往返 P95 较 2026-Q4 基线再降 ≥20% |

| 3 | 预算护栏自动化 | 目标级预算超限（v4.9 `ErrGoalBudgetExceeded`）后的自动暂停/恢复策略与回归测试 |

## 十、v5.8 生态运营规模化（Ecosystem at Scale）

> **性质**：工程稳定
> **本质跃迁**：从「机制就绪」（v4.8：验签/远程安装/统计/排行榜）到「真实用户与贡献者持续增长」。
> **立项证据**：v4.8 完成生态闭环机制（发布→分发→消费→度量），但条目规模与外部贡献者仍少。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | 第三方插件扩容 | 插件市场 ≥10 个插件，其中 ≥3 个来自团队外贡献者，安装成功率跟踪 |

## 十一、v5.9 智能进化第二轮（Adaptive Evolution II）

> **性质**：能力深化
> **本质跃迁**：从「能从失败学习」（v3.6 自愈 replan / tool_learning）到「技能与经验可流转」。

| # | 任务 | 验收标准 |
|---|------|---------|
| 1 | 技能流转闭环 | Agent 习得技能自动打包发布（manifest + 签名 + 审核流程）→ 其他 Agent 安装复用，端到端演示 |
| 2 | 跨任务迁移度量 | 相似任务复用记忆的收益量化（推理轮数/成功率对照），纳入 llm_bench |
| 3 | 自举规模化 | AP 参与 AP 开发的量化报告（基准贡献/缺陷分诊/文档生成），季度曲线持续上升 |
| 4 | 失败模式库 | 高频失败模式自动沉淀为结构化库并反哺 guardrail/tool_learning 建议 |

**验收场景**：Agent A 习得技能 → 市场发布 → Agent B 安装并使用成功，全链路日志可追溯。
