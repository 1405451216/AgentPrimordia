# AgentPrimordia v3.1 实施计划

> **文档定位**：v3.0 全部 8 个方向已落地（框架级），v3.1 聚焦**从框架到生产**——补足真实后端、打通跨组件集成、完善开发者体验。
>
> **创建日期**：2026 年 7 月 26 日
> **版本基线**：Go SDK v2.0.0 + v3.0 功能已合并 / TypeScript SDK v2.0.0 + v3.0 功能已合并
>
> 注：`package.json` 版本号仍为 v2.0.0，尚未 bump 到 v3.0.0；Go 模块无版本号字段（由 git tag 管理）。

---

## 一、V3.0 现状评估：框架级 vs 生产级

> v3.0 实现了完整的框架骨架，但多个组件处于"能编译能测试但未连接真实后端"的状态。

| 方向 | 组件 | 框架级现状 | 生产级缺口 |
|------|------|-----------|-----------|
| 4. 集群 | DistributedDiscovery | KVStore 接口 + MemKVStore | 无真实 etcd 后端 |
| 4. 集群 | RemoteMessageBus | HTTP 跨节点转发 | 未复用 A2A gRPC 通道 |
| 1. WASM | WASMToolAdapter | 注册/上传/签名 | ExecuteTool 是桩（返回 0/非 0），未通过 wazero 内存 API 传参/读结果 |
| 5. 混沌 | FaultInjector | NetworkDelay/CPU/Memory/ProcessKill 框架 | 无真实 iptables/tc/cgroup 注入 |
| 3. 学习 | KnowledgeDistiller | 字符串匹配提取事实 | 未用 LLM 做知识提取 |
| 6. 隐私 | PrivacyRouter | PII 正则检测 + 路由 | 未连接真实 WebGPU 模型加载/推理 |
| 7. CRDT | AgentCRDTClient | WebSocket 客户端 | 无同步服务器实现 |
| 8. 市场 | TemplateRegistry | 内存注册表 | 无模板打包/分发协议 |
| 2. Edge | EdgeAgentTemplate | 模板 + 脚手架生成 | 无 `ap create-edge-agent` CLI 命令 |

---

## 二、V3.1 核心目标

```
v3.1 "From Framework to Production"
  │
  ├── Phase 1: 真实后端（1-2 月）     ← P0 替换桩实现
  ├── Phase 2: 跨组件集成（2-3 月）   ← P1 打通 v3.0 组件
  ├── Phase 3: 开发者体验（3-4 月）   ← P2 CLI + UI + 部署
  └── Phase 4: 性能验证（4-5 月）     ← P2 基准测试 + 调优
```

## 三、Phase 1: 真实后端（P0）

### 3.1 etcd 服务发现后端 (`cluster/etcd_discovery.go`)

| # | 任务 | 文件 | 说明 |
|---|------|------|------|
| 1 | EtcdKVStore | `internal/agent/cluster/etcd_discovery.go` | 实现 KVStore 接口，使用 `go.etcd.io/etcd/client/v3`（build tag `etcd` 门控，参考现有 `internal/persist/etcd_checkpoint.go` 的模式） |
| 2 | Lease + KeepAlive | 同上 | 节点注册使用 etcd Lease，自动过期 |
| 3 | Watch 集成 | 同上 | etcd Watch 替代 MemKVStore 的内存 notifyWatchers |
| 4 | 测试 | `internal/agent/cluster/etcd_discovery_test.go` | 使用 testcontainers 或 mock etcd |

### 3.2 gRPC 跨节点消息总线 (`cluster/grpc_bus.go`)

| # | 任务 | 文件 | 说明 |
|---|------|------|------|
| 1 | gRPC RemoteNode | `internal/agent/cluster/grpc_bus.go` | RemoteNode 支持 HTTP + gRPC 双模式 |
| 2 | 复用 A2A gRPC | 同上 | 跨节点消息复用 `internal/agent/a2a/grpc_server.go` 的 gRPC 基础设施 |
| 3 | Protobuf 消息定义 | `internal/agent/a2a/proto/cluster/v1/cluster.proto` | ClusterMessage / ClusterReply 消息定义（遵循现有 proto 路径约定） |
| 4 | 测试 | `internal/agent/cluster/grpc_bus_test.go` | gRPC 服务器 + 客户端测试 |

### 3.3 WASM 工具真实执行 (`wasm/tool_executor.go`)

| # | 任务 | 文件 | 说明 |
|---|------|------|------|

### 4.3 隐私 × 集群：隐私感知路由

| # | 任务 | 说明 |

| 3 | 脱敏状态同步 | 脱敏映射表通过 DistributedState 同步 |

### 4.4 混沌 × Soak：CI/CD 集成

| # | 任务 | 说明 |
|---|------|------|
| 1 | Soak + 混沌联动 | Soak Test 运行期间自动注入混沌故障 |

| 3 | 退化自动报告 | Soak 退化检测自动触发混沌实验报告 |

## 五、Phase 3: 开发者体验（P2）

### 5.1 CLI 集群管理 (`cmd/ap/cluster.go`)

| 命令 | 说明 |
|------|------|
| `ap cluster init` | 初始化集群（生成配置 + 启动引导节点） |
| `ap cluster join <addr>` | 加入已有集群 |
| `ap cluster status` | 查看集群状态（节点列表/领导者/分片） |
| `ap cluster leave` | 优雅离开集群 |
| `ap cluster scale <n>` | 扩缩容节点 |

### 5.2 CLI 市场管理 (`cmd/ap/marketplace.go`)

| 命令 | 说明 |
|------|------|
| `ap marketplace search <query>` | 搜索 Agent 模板 |
| `ap marketplace install <id>` | 安装模板 |
| `ap marketplace publish` | 发布模板到市场 |
| `ap marketplace run <id>` | 从模板一键启动 Agent |

### 5.3 CLI Edge 脚手架 (`cmd/ap/edge.go`)

| 命令 | 说明 |
|------|------|
| `ap create-edge-agent <name>` | 从 Edge 模板生成项目（调用 `generateEntryFile` + `generatePackageJSON` + `generateTSConfig`） |
| `ap create-edge-agent <name> --platform deno` | 指定运行时平台（cloudflare/deno/bun） |

### 5.4 Studio Web UI 增强

| 面板 | 说明 |

## 优先级排序

```
P0（必须做）: etcd 后端 + WASM 真实执行 + LLM 蒸馏
    └── 没有这些，v3.0 的核心承诺（分布式集群/WASM 工具/自适应学习）是空壳

P1（应该做）: 跨组件集成 + gRPC 消息总线
    └── 打通组件才有整体价值，而非 8 个孤立模块

P2（最好做）: CLI + UI + 部署 + 基准测试
    └── 开发者体验和生产可信度
```
